# AI 분석 및 운용

사용자가 승인한 종목·보유 자산 분석 → 매매 제안 → 모의/실전 운용을 기존 NAMUH 앱에 연결한다.

## 동작
- AI 운용 탭에서 국내 종목을 이름으로 검색해 최대 10개 선택하거나 현재 모드의 보유 종목을 불러온다. 사용자가 선택한 범위만 분석한다.
- 선택 제공사/모델과 암호화 키를 재사용한다. 현재가, 일봉, 투자자 수급, 선택적 미국 참고 시세, 계좌번호를 제외한 보유 수량과 현금을 전송한다. 누락 자료와 조회 시점을 표시한다.
- 구조화된 결과: summary, risks, decisions[{code,target_quantity,rationale}]. 서버가 종목명, 현재 수량, 증감 수량, 매수/매도/유지, 기준가를 계산한다. 목표 수량은 주문 금액 한도가 아니다. 기존 임의 금액 한도를 복원하지 않는다.
- 분석 버튼은 주문하지 않는다. 결과별 주문 버튼은 명시적 요청으로 기존 주문 서비스에 연결한다. 실전 요청에는 live_acknowledged=true 필요.
- 설정 execution=suggest|paper|live, codes, interval_minutes(5..1440, 기본30), objective, include_us. 기본 분석만. 자동 운용은 별도의 시작 동작 필요. 주문·자동매매 화면의 기존 엔진이 먼저 실행 중이어야 한다.
- 자동 주기는 평일 KRX 정규장 시간 범위에서 실행한다. 휴장일 달력은 없으므로 당일 일봉과 양수 거래량이 확인되지 않으면 자동 주문을 보류한다. 일봉 지연 시 주문이 보류되는 제한을 UI/문서에 명시한다.
- 앱 재시작, 모드/계좌/AI 연결 설정 변경, 엔진 정지, 오류 발생 시 자동 운용은 정지한다. 분석 중 정지해도 결과가 뒤늦게 주문으로 이어지지 않는다.
- 주문 전 분석 유효기간(5분), 현재가 재조회, 설정 버전, 잔고 재조회, 미체결 종목 중복 여부를 확인한다. 가격은 새 현재가를 지정가로 사용하고 기준가 대비 3% 초과 변화 시 재분석을 요구한다.
- 영속 실행 기록과 기존 멱등 주문 ID를 사용한다. 불확실한 전송은 재시도하지 않는다. 이미 접수된 주문은 AI 정지만으로 취소되지 않으며 기존 긴급정지 화면에서 관리한다.

## 구조
- backend/ai/generation.py: 제공사별 생성 HTTP 어댑터, 엄격한 결과 스키마 검증.
- backend/ai/context.py: NAMUH 데이터/계좌 정보 최소화, 종목 명부 검증.
- backend/ai/operation.py: SQLite 실행 기록, 분석, 주문, 정지 가능한 주기 작업.
- backend/ai/operation_api.py: 버전 및 요청 헤더 검증, 작업 상태 API.
- frontend/src/components/AIOperation.jsx, AIOperation.css: 기존 다크 테마에 통합.

## 검증
외부 HTTP를 가짜 transport로 대체하여 세 제공사 응답/거절/오류를 검증한다. 임시 SQLite와 가짜 시세/증권사로 중복 주문, 정지 경합, 설정 변경, 잔고 부족, 재시작 복구를 검증한다. 실제 실전 주문은 테스트하지 않는다. 전체 회귀 테스트와 lint/build 후 EXE를 생성한다.
