# 실전 주문 및 모드 설정

사용자가 승인한 범위: 국내주식 현금 주문(매수/매도/정정/취소), 주문·체결·미체결 조회, 모의/실전 전환 설정 및 가격 조건 자동 주문. 구현/검증 중 실제 주문 전송은 하지 않는다.

- [x] 공식 명세 기반 NAMUH 주문 게이트웨이 및 계약 테스트. 조회·주문 성공 코드를 구분하고 전송 결과 불확실성을 보존한다.
- [x] SQLite 실전 요청 원장 및 설정 서비스. 전송 전 기록, 요청 식별자별 중복 방지, 재시작 시 sending→unknown, 중단/모드 변경 버전 검사.
- [x] 실전 지정가 현금 주문과 주문 가능 수량 확인, 원주문 잔량 가격 정정/취소, 당일·과거 날짜 체결 조회 및 상태 동기화. KRX 현금 지정가를 사용하며 신용·공매도는 제외한다.
- [x] 실전 일회성 가격 조건, 수동 실행/중단, 긴급정지 및 해당 앱이 접수한 당일 미체결 취소. 취소 실패와 결과 불확실성은 표시한다.
- [x] 설정 화면: 모드, 마스킹 계좌, 실전 주문당 한도/일일 매수 한도. 실제 주문 화면: 보유·주문 가능 수량, 주문/조건 입력, 증권사 주문 내역, 로컬 전송 내역 및 불확실 응답 확인 처리.
- [x] 모의 엔진과 통합 모드 가드: 모드 변경·재실행 시 자동 실행 정지, 모의 주문이 실전에 전달되지 않음. 시세·계좌 조회로만 실 API 검증, 가짜 전송으로 주문 흐름 검증. UI/리뷰/EXE 1.5.0 빌드.

실전은 서버가 기록한 mode/account/version을 따르며 클라이언트가 임의 계좌를 주문에 지정할 수 없다. 일일 매수 금액은 앱 접수 금액을 보수적으로 누적하고 취소해도 복원하지 않는다. 재시작 또는 모드 변경 후 실행 버튼을 누르기 전까지 신규 실전 주문도 잠금 상태다. 설정에 실전 모드를 선택했다고 주문이 발생하지 않는다. 응답 불확실성 해제는 증권사 내역을 보고 사용자가 직접 확인해야 한다. 이미 전송한 주문의 원자적 철회는 보장하지 않는다.


## 검증 결과

- Python 전체 76개, JavaScript 중복 요청 1개 테스트 통과. ESLint 통과 (기존 module type 경고 유지).
- 공식 명세의 매수 00048/매도 00047/정정 00164/취소 00192 성공 코드 및 요청 필드로 HTTP 모의 계약 검증.
- 실제 계좌·현재가·잔고·현금 매수/매도 가능 수량·주문내역 조회 통과. 주문 전송 경로를 검증 코드에서 차단. 주문 내역 없음 11512 + Output_0=[] 실제 관측을 회귀 테스트로 추가. 매수 가능 수량은 실제 현재가를 사용해 조회.
- 가짜 계좌와 임시 DB UI에서 실전 설정 저장/잠금 해제/수량 조회/매수/정정/취소/모의 전환 검증. 실제 주문 전송 0건.
- 독립 리뷰의 취소 한도, 중단 경합, 중복 긴급정지, 전송 중 긴급 접근, 거래일 변경, 조건 시각 경계 문제를 회귀 테스트로 수정·재검토.
- 1.5.0 무설치 EXE 및 설치 파일 빌드 성공. 패키지에서 설정 저장·복원, 모의 주문 취소, 실전 요청 모드 가드, 재시작 정지 검증. 키가 없는 임시 설정에서 실행.

제한: 국내 현금/KRX/지정가 범위, 체결 REST 15초 조회. 실제 증권사 주문 전송 결과는 실행하지 않았으므로 미검증이며 사용자가 직접 주문 화면에서 실행한다. 실전 조건은 평일 09:00~15:20 운영 창을 적용하고 휴장일 캘린더는 포함하지 않는다.
