# 모의 주문·자동매매 기반 구현 계획

**승인 범위:** 사용자가 승인한 주문·체결 관리 기반과 시뮬레이션 단계. 실제 주문 API 호출은 포함하지 않는다.
**구조:** NAMUH 시세 읽기 → 독립 모의 엔진 → SQLite 원자적 상태 저장 → FastAPI → React 모의매매 화면.

- [x] 주문 엔진: 지정가 매수/매도, 부분 체결, 가격 정정, 잔량 취소, 가상 현금/주식 예약, 중복 요청 방지. 테스트부터 작성한다.
- [x] 조건 실행: 가격 이상/이하 조건당 한 번 주문, 최대 10개 감시 종목, 약 10초 주기. 정지/재시작 경합 및 시세 실패를 검증한다.
- [x] API·화면: 모의 주문, 조건 등록/해제, 실행/일시정지/긴급정지, 잔고·주문·진단 내역. 실제 계좌와 분리한다.
- [x] 단위/통합 테스트, lint, UI 확인, 리뷰, EXE 1.4.0 빌드 및 패키지 실행 확인.

## 동작 계약

초기 가상 현금 1,000만 원. 주문당 지정가 기준 100만 원, 종목당 보유 원가+매수 예약금 300만 원 한도. 공매도·신용 없음. 지정가 주문만 지원한다. 가격 변경은 미체결 잔량에 적용되며 이미 체결된 수량은 유지한다.

시세를 새로 조회한 후 해당 가격에 지정가 조건이 맞으면 종목당 한 주기에 최대 10주를 FIFO로 가상 체결한다. 호가/잔량/수수료/세금/슬리피지/실제 체결 가능성을 재현하지 않는다. 장외에도 API 마지막 가격을 이용한 동작 시험이 가능하며 수익성 검증이나 증권사 모의투자가 아니다.

SQLite에 현금·보유·주문·조건·최근 기록을 한 트랜잭션으로 저장한다. 재시작하면 수동 실행 전까지 정지한다. 조건 주문은 성공 또는 한도 거절 시 재실행하지 않고 결과를 남긴다. 긴급정지는 미체결 잔량 취소 및 대기 조건 해제를 포함한다. 늦게 도착한 시세는 정지/재시작 이후 적용하지 않는다. 시세 오류 시 체결하지 않으며 오류를 표시한다.


## 검증 결과

- Python 전체 50개 테스트 통과, JavaScript 중복 요청 키 테스트 1개 통과.
- ESLint 통과 (기존 MODULE_TYPELESS_PACKAGE_JSON 경고 유지).
- 브라우저에서 지정가 접수·정정·체결·가격 조건 매도·가상 잔고·긴급정지 확인. 테스트 가격과 별도 임시 DB 사용.
- 코드 리뷰에서 미체결 표시 누락, 내부 요청 키 충돌, 응답 불확실 시 재시도 키 보존, 긴급정지 이후 지연 요청 경합을 재현하고 수정. 회귀 테스트 통과 및 재검토 완료.
- 1.4.0 무설치 EXE/설치 파일 빌드 성공.
- 패키지 백엔드에서 실제 나무 시세로 모의 1주 체결, 재실행 시 잔고·주문 복원/정지 상태, 오래된 실행 요청 거절 확인. 임시 DB 사용, 실제 주문 전송 0건.
