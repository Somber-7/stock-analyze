# Stock Analyze · 나무증권

NAMUH PLUG 기반 국내주식 조회 대시보드입니다.
React/Vite 화면, FastAPI 백엔드, Electron 데스크톱 실행을 사용합니다.

## 실행

Windows에서는 다음 중 하나를 실행합니다.

- 무설치 실행: `dist-electron-namuh/Stock Analyze 1.21.1.exe`
- 설치/업데이트: `dist-electron-namuh/Stock Analyze Setup 1.21.1.exe`

exe는 빈 로컬 포트를 자동으로 배정받으므로 기존 8000번 포트와 충돌하지 않습니다.
앱을 닫으면 자신의 백엔드 프로세스도 종료합니다. 이미 실행 중인 새 앱을 다시 열면 기존 창을 표시합니다.
설치 파일을 사용해 이전 버전을 업데이트할 때는 기존 앱을 종료합니다.

소스에서 실행하려면 프로젝트의 `start.bat`을 사용합니다.
이 파일은 소스 폴더의 최신 React 빌드와 Python 백엔드를 Electron에서 실행합니다.

기본 Python은 `%USERPROFILE%\miniconda3\envs\stock-analyze\python.exe`입니다.
다른 환경은 `STOCK_PYTHON` 환경변수에 Python 실행 파일 경로를 지정합니다.

처음 환경을 구성하거나 소스를 수정한 경우:

```powershell
conda activate stock-analyze
pip install -r requirements.txt
cd frontend
npm ci
npm run build
npm run electron
```

웹으로 실행하려면 프로젝트 루트에서 `python run.py` 실행 후
`http://127.0.0.1:8000`에 접속합니다. 개발 중에는 별도 터미널에서
`cd frontend; npm run dev`를 사용할 수 있습니다.

## 인증 설정

소스 실행은 프로젝트 루트의 `Api_Key.txt`를 자동으로 읽습니다.
exe는 `%APPDATA%\stock-analyze`의 설정을 사용합니다. 이 PC에는 기존 키와 토큰 캐시를 준비했습니다.
설정이 없는 다른 PC에서는 처음 실행할 때 키 텍스트 파일을 선택하면 앱 설정 폴더에 저장합니다.

```text
APP Key: 발급받은 App Key
APP Secret: 발급받은 App Secret
```

또는 `.env`에 `NAMUH_APP_KEY`, `NAMUH_APP_SECRET`을 함께 설정합니다.
두 환경변수가 모두 설정돼 있으면 키 파일보다 우선합니다.
키를 변경한 뒤에는 백엔드를 재시작합니다.

토큰은 `.namuh_token_cache.json`에 만료시각과 함께 저장하여 재사용합니다.
키·토큰 파일은 Git 및 설치 패키지에 포함하지 않습니다.
계좌는 API에서 조회하며 1개이면 자동으로 표시하고 여러 개이면 직접 선택합니다.
화면 계좌번호는 끝 4자리만 표시합니다.

## 기능과 데이터 기준

- 1.21.1: 모든 화면의 본문 최대 폭을 1240px로 통일해 메뉴를 옮겨도 본문 위치와 좌우 여백이 바뀌지 않습니다(이전: 대부분 1480px, AI 분석·운용 1240px, 설정 1040px). 스크롤바 자리를 항상 확보해 내용 길이에 따라 본문이 좌우로 밀리지 않습니다. 창 크기를 바꾸면 여백은 창 폭에 맞춰 달라집니다.
- 검증: 최대화(2048px)와 1280px 창에서 8개 화면의 본문 시작 위치와 폭이 모두 같음을 확인했습니다. ESLint와 Node 테스트 통과.

- 1.21.0: Windows 기본 상단바를 없애고 최소화·최대화·닫기 버튼을 앱 상단 워크스페이스 바 오른쪽에 넣었습니다. 버튼은 Windows 기본 버튼이며 색만 다크 테마에 맞췄습니다. 화면 위쪽 띠(워크스페이스 바와 사이드바 로고 포함)를 끌어 창을 옮기고 두 번 눌러 최대화합니다. 워크스페이스 바는 스크롤해도 위에 고정되고 항상 한 줄로 표시됩니다. 상단 시계는 날짜와 시각을 한 줄로 보여 주며(웹 실행 포함), 좁은 창에서는 시계 아이콘을 숨기고 공간이 부족하면 경로 표시를 줄입니다. Windows 11 스냅 레이아웃, 창 가장자리 크기 조절, 화면 확대/축소는 그대로 동작합니다. 웹 브라우저 실행 화면은 바뀌지 않습니다.
- 저장·추가·등록 같은 작업 결과 안내와 방금 누른 작업의 일회성 실패는 오른쪽 아래 토스트로 표시합니다. 안내는 4.5초 뒤 사라지고 실패는 닫기 전까지 남으며, 가격 알림과 함께 쌓입니다. 주문·체결 관련 오류와 결과, 조회 실패처럼 화면 상태를 설명하는 오류, 시세·데이터 경고, 버튼을 쓸 수 없는 이유는 기존처럼 화면 안에 표시합니다.
- 검증: Python 308개·Node 20개 테스트와 ESLint 통과. 가짜 계좌 화면을 띄운 실제 Electron 창에서 1280·900px·최대화·넓은 화면·확대/축소 상태의 창 이동 영역과 버튼 판정, 토스트 표시·자동 닫힘·가격 알림과의 배치를 확인했습니다. 실제 주문은 실행하지 않았습니다.

- 1.20.1: 재무 문장 검증에서 현금 유출·손실 규모와 금액의 부호를 구분하고, 다른 주어에 걸린 증감·모호한 표현을 확정 불일치로 차단하지 않습니다. 직접적인 재무 비교의 오류는 계속 차단합니다. 실패한 분석에는 검증 상세(종목·계정·응답 항목·문장)와 실제 반환된 토큰 사용량을 보관합니다. 이전 실패 응답은 보관되지 않았으므로 소급 복원하지 않습니다.

- 1.20.0 분석 개선: 반기 현금흐름은 전년 동기와 비교합니다. 매출·손익·영업현금흐름의 명시적인 개선·악화 문장은 비교값 유무와 방향을 검사하고, 불일치 시 결과를 채택하지 않습니다. 이 검사는 한정된 표현에 대한 검증이며 모든 자연어 사실의 정확성을 보장하지 않습니다.
- 종목 의견과 수량 결정 보류를 구분하고, 기존 재검토 영역에 20·60봉 이동평균 전환 기준을 표시합니다. 기준값은 분석 당시 계산값이며 다음 분석에서 갱신됩니다. 주문·손절 조건이 아닙니다. 현금성 자산 비중과 선택/미선택 보유 주식 비중을 모델 입력에 포함합니다.
- 뉴스 발췌의 관련 종목·기사 링크·중복 문단을 정리하고 재배포 기사 중복을 줄입니다. DART 재무 주요계정이 확보된 종목은 웹 재무보고서 검색을 생략하고 뉴스만 조회합니다. 변경된 분석 지침은 새 분석에 적용되며 기존 리포트 원문을 다시 작성하지 않습니다.

- 포트폴리오 현재가에도 `가격 (전일 등락률)`을 표시합니다. 잔고를 먼저 보여준 뒤 중복 종목을 제외하고 최대 3개씩 시세를 조회하며, 새로고침할 때 갱신합니다. 가격과 등락률은 같은 시세 응답을 사용합니다. 평가금액·평가손익은 잔고 조회 기준으로 유지하고, 시세 조회 시각은 현재가에 마우스를 올리면 확인할 수 있습니다. CMA는 주식 시세 조회에서 제외합니다.
- 상단 KST 시계는 PC 시각을 한국 시간으로 변환해 날짜·요일·시각을 초 단위로 표시합니다. 시계 갱신은 API를 호출하지 않습니다.

- 숫자 가독성: 시세·평가손익을 `금액 (증감률)`로 묶고 상승은 빨강, 하락은 파랑, 보합·미확인은 중립색으로 표시합니다. 포트폴리오는 매입금액 대비 수익률, 시세 화면은 전일 대비, AI 기준가는 지난 분석 대비, DART는 표시된 비교 보고기간 대비입니다. 새로운 카드·조회 항목을 추가하지 않으며, 계산 기준이 0·음수·미확인이면 새 증감률을 만들지 않습니다.

- 포트폴리오의 **오늘 확인할 항목**: 저장된 관심종목 등락, 오늘 발생한 가격 알림, 조회 계좌의 미체결 주문, 같은 조건의 최근 AI 판단 변화. 관심종목은 요약 조회 시점 2분 이내 캐시만 사용하며 새로고침 전까지 자동 갱신하지 않습니다. 미체결·AI 요약은 조회 계좌와 실전 주문 설정이 일치할 때 표시합니다.
- AI 리포트의 **주문 계획 미리보기**: 예상 매수·매도 합계, 매수 후 현금, 현금 부족, 종목별 예상 금액·목표 비중·조회 당시 매수 여력. 1.15.0에서 새로 생성한 분석부터 저장됩니다. 매도 예상대금은 매수 재원에 합산하지 않으며 수수료·세금·가격 변동은 제외합니다. 실제 주문 검증은 기존 종목별 주문 경로가 수행합니다.

- 나무증권 실계좌 국내주식 잔고·예수금·평가손익, 연속조회 및 새로고침
- 나무 API가 제공하는 국내 KRX 시장 현재가와 종목명/코드 검색 (별도 거래소 로그인 없음)
- 일·주·월봉 기본 250개, 1분·5분봉 최근 최대 5개 거래일
- 캔들 차트와 5·10·20·60·120 이동평균선
- 국내 종목명 검색은 나무 공식 종목정보파일만 사용합니다.
- 미국 시장 참고: 다우 산업지수, SPY·QQQ·SOXX ETF, 엔비디아·AMD·마이크론 시세
- 미국 화면은 1분 간격 조회와 종목별 오류 표시를 지원합니다. ETF 가격은 지수 수치와 다릅니다. 시세 기준일과 조회 시간을 표시하며 장전·장후 및 지연 시세가 포함될 수 있습니다.
- 시가총액 TOP 100: 나무 종목파일의 전일 시가총액으로 코스피·코스닥 주식(우선주 포함, ETF·ETN 제외)을 선정합니다. 순위는 현재가에 따라 바뀌지 않습니다.
- TOP 100 목록은 파일에서 즉시 표시하고 현재가는 순차 갱신합니다. 화면을 보는 동안 한 회차 완료 후 60초 뒤 재조회하며 종목별 조회 시각·오류를 표시합니다. 화면을 떠나면 추가 수집을 중단합니다.
- 종목파일은 날짜 변경 시 또는 1시간 경과 시 다시 확인합니다. 파일 수신 시각은 실제 순위 기준 거래일과 다르며 원본 파일에 기준 거래일 필드는 없습니다.
- 별도 거래소 로그인과 외부 시세 수집은 사용하지 않습니다.

포트폴리오의 총 평가금액은 국내주식 평가액(`tot_eal_amt`)이며 예수금은 별도 표시합니다.
신용·현금 등 동일 종목의 잔고 유형은 별도 행으로 표시합니다.
현재가 API에서 제공하지 않는 EPS 등의 값은 임의로 채우지 않습니다.
조회 오류는 0원이나 빈 잔고로 대체하지 않고 오류로 표시합니다.

## Windows 설치 파일 다시 만들기

해당 Python 환경에 PyInstaller를 설치하고 `build.bat`을 실행합니다.
스크립트는 현재 프로젝트 경로를 기준으로 빌드하며 `.env`를 번들하지 않습니다.
빌드 결과는 `dist-electron-namuh`에 생성됩니다.

새 설치 앱의 설정 폴더는 Electron의 `app.getPath('userData')`입니다.
현재 앱 이름 기준 `%APPDATA%\stock-analyze`이며, 여기에 `Api_Key.txt`를 넣습니다.
나무 API 키만 설정하면 됩니다. 나무 종목 목록은 `.namuh_stocks.json`에 저장됩니다.
기존 외부 종목·시장 순위 캐시는 사용하지 않습니다.

- 모의 주문 금액 제한은 없습니다. 가상 현금·매도 가능 수량은 검사하며 감시 종목/대기 조건은 최대 10개입니다.

## 1.5.0 실전 주문 및 설정

**설정** 페이지에서 모의/실전 모드와 API 등록 실계좌를 저장합니다. 최초 기본값은 모의 모드입니다. 선택 모드는 저장되지만 모드 변경·앱/서버 재시작 후 실행은 정지합니다. 실전 모드 저장만으로 주문이 발생하지 않습니다.

실전 사용 순서:

1. 설정에서 실전 모드와 계좌를 고르고, 실제 계좌 주문임을 확인하여 저장합니다.
2. 주문·자동매매에서 **실전 실행 시작**의 내용을 확인합니다.
3. 국내 종목코드·수량·지정가를 입력합니다. 주문 가능 수량은 미수를 포함하지 않는 현금 기준입니다.
4. **실전 주문 내용 확인**에서 계좌·종목·매수/매도·수량·금액을 확인하고 직접 전송합니다.
5. 증권사 주문·체결 내역에서 접수 번호, 부분 체결, 미체결 잔량, 취소 수량을 확인합니다. 당일 정상 KRX 현금 지정가 주문의 잔량 가격 정정·취소가 가능합니다. 날짜별 내역을 조회할 수 있으며 화면이 열려 있으면 15초마다 갱신합니다.

실전 가격 조건도 지원합니다. 가격 이상/이하 조건당 한 번만 지정가 주문합니다. 평일 09:00~15:20에 약 10초 주기로 판단하며 휴장일은 별도로 판정하지 않습니다. 주문은 전송 직전에 실행 상태·날짜·시세 판단 유효시간을 검사합니다. 수동 주문 시간/가격 가능 여부는 증권사 응답을 따릅니다. 국내 현금/KRX/지정가 범위이며 시장가·신용·공매도·SOR/NXT·해외 주문은 포함하지 않습니다.

**중단**은 신규 주문과 조건 실행을 잠급니다. 증권사에 접수된 미체결은 남습니다. **긴급정지 · 앱 주문 취소**는 해당 앱이 접수한 당일 KRX 미체결의 취소를 요청하고 접수/거절/확인 대기 건수를 표시합니다. 다른 매체의 주문은 자동 취소하지 않습니다. 이미 체결된 거래는 되돌리지 않습니다.

전송 전 `.live_trading.sqlite3`에 요청을 저장합니다. 응답 불확실, 비정상 응답, 전송 중 앱 종료는 자동 재전송하지 않습니다. 확인 대기 항목이 있으면 신규 주문을 잠그며 나무 주문 내역에서 직접 접수 여부를 확인한 뒤 주문번호 연결 또는 미접수 확인을 처리합니다. 알려지지 않은 주문 응답 코드는 임의로 미접수로 간주하지 않습니다. 주문 요청은 식별자/계좌/날짜/모드 버전으로 보호하며 변경된 상태의 오래된 요청은 차단합니다.

앱 자체의 주문당·일일 매수 금액 제한은 없습니다. 실전 주문 전 나무의 주문 가능 수량을 확인하고, 가격 상향 정정 시 필요한 추가 현금도 확인합니다. 접수 금액 기록은 남지만 한도로 사용하지 않습니다.

실전 DB와 모의 DB는 각각 저장되며 EXE에서는 `%APPDATA%\stock-analyze`, 소스에서는 프로젝트 루트에 있습니다. 키·토큰·거래 기록은 설치 파일에 포함하지 않습니다.

검증: 실제 API는 계좌·현재가·잔고·주문내역·매수/매도 가능 수량 조회까지 확인했습니다. 실제 주문 전송은 하지 않았으며 매수·매도·정정·취소 및 조건 실행은 공식 계약의 HTTP 모의 응답과 가짜 계좌 UI로 검증했습니다. `python tests/manual_live_ui.py`는 가짜 계좌와 임시 DB만 사용하는 UI 검증 서버입니다.

## 1.5.1 주문 종목 이름 표시

모의·실전 주문 화면에서 종목명 또는 코드를 검색합니다. 이름은 검색 목록에서 선택하고, 정확한 6자리 코드는 종목명을 자동 확인합니다. 선택한 종목의 이름과 코드를 함께 표시하며, 입력을 바꾸면 이전 선택·지정가·주문 가능 수량을 초기화합니다. 종목 선택 전에는 주문과 조건을 접수할 수 없습니다.

주문 확인창, 기존 주문·조건·실전 전송 기록에도 종목명과 코드를 함께 표시합니다. 이름은 나무 공식 종목파일을 사용하며, 기록의 이름을 붙이기 위해 종목별 시세 API를 호출하지 않습니다. 종목파일에서 찾을 수 없는 과거 기록은 코드와 종목명 확인 불가 안내를 표시합니다.

## 1.5.2 영문 포함 국내 종목코드 수정

## 1.7.0 관심종목·가격 알림·투자자별 수급

- **관심종목·알림** 메뉴에서 이름 또는 코드로 종목을 추가합니다. 종목 조회 화면에서도 추가할 수 있으며, 목록에서 차트·수급·주문 화면으로 이동합니다. 채비처럼 영문을 포함한 국내 종목코드도 지원합니다.

- 알림은 **앱과 서버가 켜져 있을 때**, 한국 시간 평일 09:00–15:30에 감시합니다. 휴장일은 별도 구분하지 않으며 나무 API가 반환한 가격으로 판단합니다. 오류·0원·비정상 값·30초 넘게 걸린 응답으로는 발동하지 않습니다. 앱 종료 중 알림이나 지나간 가격 도달을 소급하지 않습니다. 가격 알림은 주문을 실행하지 않습니다.

## 1.8.0 AI 연결 설정

**설정 → AI 연결 설정**에서 OpenAI·Claude(Anthropic)·Gemini의 API 키와 모델을 각각 저장하고 사용할 제공사를 선택합니다. 입력란이 비어 있으면 기존 키를 유지하며, 삭제 버튼은 선택한 제공사의 저장 키만 지웁니다. 모델 목록에서 선택하거나 정확한 모델 ID를 직접 입력할 수 있습니다.

**인증 확인 · 모델 조회**는 공식 API의 모델 목록 GET 요청만 수행합니다. 생성 호출·자동 분석·주문은 실행하지 않으며 모델별 생성 권한, 잔액, 응답 성능을 보장하지 않습니다. 이번 버전은 AI 연결 설정까지 제공하며 AI 분석·운용 엔진 연결은 후속 작업입니다. 기존 모의/실전 매매 설정과 별도로 저장합니다.

키는 Windows 사용자 범위 DPAPI로 암호화해 `.ai_settings.enc`에 저장하며 API 응답·브라우저 저장소에 반환하지 않습니다. 저장 위치는 소스 실행 시 프로젝트 폴더, EXE 실행 시 `%APPDATA%\stock-analyze`입니다. 다른 Windows 계정으로 옮기면 재입력이 필요합니다. 동일 계정의 실행 중인 프로그램까지 격리하는 보안 장치는 아닙니다. 키와 설정은 EXE에 포함하지 않습니다.

OpenAI 키는 펼침 메뉴에서 서버 기준 폴더의 `Api_Key.txt`로부터 가져올 수 있습니다. 한 개의 OpenAI 키만 식별되면 암호화 저장하며, 원본 파일은 수정하지 않습니다. EXE에서는 프로젝트 파일이 아닌 사용자 앱 데이터 폴더의 파일을 읽으므로 새 키는 화면 입력을 권장합니다.

연결 계약: [OpenAI 모델 목록](https://developers.openai.com/api/reference/resources/models/methods/list), [Anthropic 모델 목록](https://platform.claude.com/docs/en/api/models/list), [Gemini 모델 목록](https://ai.google.dev/api/models). 모델 목록은 조회 시점의 계정 권한에 따라 달라집니다.

## 1.9.0 AI 분석·운용

**AI 분석·운용**에서 종목명으로 국내 종목을 최대 10개 선택하거나 현재 모드의 보유 종목을 불러오고 설정을 저장합니다. **지금 분석하기**는 선택한 AI에 현재가·최근 60개 일봉·투자자 수급·보유 수량·현금·선택적 미국 참고 시세를 전달하고 종목별 목표 보유 수량과 근거를 반환합니다. 계좌번호·API 키는 분석 입력에서 제외합니다. 생성 요청에는 제공사의 API 요금이 적용될 수 있습니다.

분석 결과에는 제공사·모델·시각·토큰 사용량(미제공은 —)·누락 자료·위험·현재/목표 수량이 남습니다. **분석 버튼은 주문하지 않습니다.** 개별 제안의 주문 버튼은 현재 매매 모드의 기존 주문 엔진에 연결되며 실전은 명시적 확인이 필요합니다. 주문 엔진을 먼저 시작하세요.

자동 운용 방식은 **자동 분석·제안만 / 자동 모의 주문 / 자동 실전 주문** 중 선택합니다. 설정 저장 후 **자동 운용 시작**을 눌러야 주기적으로 실행합니다. 기본 주기는 30분이며 5~1440분으로 설정할 수 있습니다. 자동 주문 모드와 현재 매매 모드가 일치하고 기존 주문 엔진이 실행 중이어야 합니다. 자동 실전 시작 시 이후 주기에도 실제 주문이 전송됨을 확인해야 합니다. 주문 금액 한도는 추가하지 않았으며 기존 현금/매도 가능 수량 검증을 적용합니다.

AI 주문·자동 주기는 한국 시간 평일 09:00~15:20에 작동합니다. 휴장일 달력은 없으며 자동 주문은 당일 거래 일봉과 양수 거래량이 확인되어야 합니다. 따라서 당일 일봉이 지연되면 주문을 보류할 수 있습니다. 주문은 목표 수량과 분석 시 보유 수량의 차이만큼 새 현재가를 지정가로 전송합니다. 미체결 종목, 보유 수량 변경, 분석 요청 후 5분 경과, 기준가 대비 3% 초과 가격 변화, 시세 확인 후 30초 경과, 모드·계좌·연결 변경 시 주문하지 않습니다. 늦거나 실패한 응답은 자동으로 재전송하지 않습니다.

앱/서버가 켜져 있어야 작동합니다. 재시작하면 자동 운용은 정지 상태이며, 설정 변경·주문 엔진 정지·오류 발생 시에도 멈춥니다. **AI 운용 정지는 이미 접수된 주문을 취소하지 않습니다.** 기존 주문·긴급정지 화면에서 체결 및 미체결을 확인하세요. 분석/실행 기록은 `.ai_operation.sqlite3`에 저장되고 EXE에서는 `%APPDATA%\stock-analyze`를 사용합니다. 실제 생성 성능과 자동 매매 수익성은 별도 검증 대상입니다.

생성 계약: [OpenAI 구조화 응답](https://developers.openai.com/api/docs/guides/structured-outputs), [Anthropic 구조화 응답](https://platform.claude.com/docs/en/build-with-claude/structured-outputs), [Gemini generateContent](https://ai.google.dev/api/generate-content). 선택 모델이 해당 구조화 응답 API를 지원해야 하며, 모델 목록에 보이는 것만으로 생성 권한을 보장하지 않습니다.

UI 검증: `python tests/manual_ai_ui.py`는 임시 DB·가짜 AI 응답·가짜 주문만 사용합니다. 실제 키 또는 실계좌 주문을 사용하지 않습니다.

1.9.0 검증: Python 테스트 158개, JavaScript 요청 식별자 테스트 및 ESLint 통과. 화면에서 채비 선택·설정 저장·분석 결과·모의 주문 접수를 확인했습니다. 저장된 OpenAI `gpt-5.6-terra`로 공개 시세를 사용하는 생성 1회 성공(입력 2,080 / 출력 359토큰). 이 확인에는 계좌 정보를 전송하지 않았으며 실제 증권사 주문도 하지 않았습니다. Portable·설치 EXE를 빌드하고 Portable의 새 AI API, 기존 키/모델 유지, AI/매매 엔진 정지를 확인했습니다. Anthropic·Gemini 생성은 가짜 HTTP 응답으로 계약 검증했으며 실제 계정 호출은 하지 않았습니다.

## 1.9.1 분석 프롬프트 프리셋

AI 분석·운용의 지침 입력란 위에서 **균형 분석 / 보유 자산 점검 / 수급 중심 / 추세·눌림목 점검 / 미국 반도체 영향 / 신규 매수 신중 검토** 중 하나를 고를 수 있습니다. 지침을 미리 보고 **프리셋 적용**을 누르면 입력란에 채워집니다. 적용 직후에는 이전 문구로 되돌릴 수 있고, 직접 수정하면 ‘직접 작성·수정’으로 표시합니다. 최종 지침은 기존 **설정 저장**으로 저장됩니다. 프리셋 선택·적용은 분석이나 주문을 시작하지 않습니다. 미국 반도체 프리셋은 미국 참고 시세 옵션이 꺼져 있으면 안내를 표시하며, 옵션을 임의로 변경하지 않습니다.

## 1.9.2 분석 준비 안내·비주식 자산 제외

보유 종목 조회에서 CMA 발행어음 등 비주식 자산과 나무 국내 종목 목록에서 확인되지 않는 항목을 제외합니다. AI에 전달하는 주식 보유 목록에도 동일하게 적용하며 제외 자산을 가용 현금에 합산하지 않습니다. 제외된 항목이 있으면 분석 참고 사항에 표시합니다. 분석 대상 추가 시 화면에서도 종목 목록을 확인합니다.

‘지금 분석하기’를 **1회 분석**으로 바꾸고 비활성화 이유를 버튼 위에 표시합니다. 선택한 종목이나 지침이 저장되지 않았다면 버튼 옆의 **분석 설정 저장**을 눌러 저장한 뒤 분석할 수 있습니다. 이 과정에는 실전 주문 확인이나 주문 엔진 실행이 필요하지 않습니다. Python 테스트 160개와 ESLint·프런트엔드 빌드를 통과했습니다.

## 1.9.3 Tavily 키 설정

1.9.3 당시에는 Tavily **키 관리**만 지원했습니다. 키 저장 시 인증 확인이나 검색 요청을 보내지 않으며, 실제 검색과 분석 반영은 아래 1.11.0에서 추가했습니다. Python 테스트 164개, ESLint, EXE 빌드 및 가상 키를 이용한 화면 저장·삭제·입력 초안 유지 검증을 통과했습니다.

## 1.10.0 설정 탭·분석 근거 개선

설정 화면을 **AI 모델 / 웹 검색 / 매매·계좌** 탭으로 나눕니다. 설정 탭 사이를 이동해도 입력 중인 내용은 유지됩니다. Tavily 키 입력·교체·삭제는 **웹 검색** 탭에 있습니다. 실제 Tavily 검색 결과 수집과 분석 반영은 1.11.0에서 추가했습니다.

AI 입력에서 **예수금(dca)**과 **계좌 100% 주문가능금액(orr_pbl_amt4)**을 구분합니다. 각 종목의 기준가로 매수가능수량 API를 조회해 **미수 미발생 현금 가능금액·수량(csh_orr_pbl_amt/qty)**도 전달합니다. 종목별 금액을 합산하지 않으며, 조회 실패나 누락은 0이 아닌 미확인(null)입니다. 기존 주문 엔진의 주문 직전 가능금액 검증을 유지합니다.

CMA 등 국내 종목 목록 밖의 항목은 매매 대상에서 제외하되 이름·평가액을 기타 자산으로 제공합니다. 조회 계좌의 총자산(tot_aet_amt)·순자산(nas_amt)은 별도로 표시하며 CMA 평가액을 현금에 합산하지 않습니다. 총자산이 유효하면 보유 수량×기준가/계좌 총자산 비중을 계산합니다. 이 값은 조회 계좌 범위이며 계좌 밖 자산까지 포함한 투자자의 전체 자산은 아닙니다. 필드 의미는 로컬에 저장한 나무 공식 가이드 `docs/namuh-full-api-reference.json`의 잔고·매수가능수량 명세를 따릅니다.

새 결과에는 **판단 가능(supported)** 또는 **판단 유보(defer)** 상태와 재검토 조건이 필요합니다. 판단 유보는 보유가 유리하다는 의미가 아니며 현재 수량과 다른 목표를 반환하면 분석을 거부합니다. 수량이 같더라도 유보 상태는 수동·자동 주문 대상에서 제외됩니다. 이전 분석 기록은 수정하지 않으며 이전 형식이라는 안내를 표시합니다.

분석 화면에서 **투자기간: 미지정 / 단기(1개월 이내) / 중기(1~6개월) / 장기(6개월 이상)**를 선택할 수 있습니다. 기존 설정은 미지정으로 읽고 임의 기간이나 투자금액 한도를 부여하지 않습니다. 최근 5·20구간 종가 수익률, 20·60봉 단순이동평균, 20개 일간 수익률의 표본 표준편차(비연율화), 마지막 봉 거래량/직전 20봉 평균, 최근 최대 5개 제공 수급 행의 부호·연속 순매수 관측을 Python에서 계산해 전달합니다. 필요한 데이터가 부족하면 미확인입니다. 장중 미완성 봉·거래일 누락·수정주가 적용 여부의 한계도 설명합니다.

분석 결과에 사용한 계좌 자산·투자기간·종목별 지표·주문가능금액을 기록하여 화면에서 확인할 수 있습니다. 같은 자료를 반복 서술하는 대신 정량 지표는 접을 수 있는 상세 영역으로 제공합니다. Python 테스트 172개와 ESLint를 통과했으며 임시 DB·가상 응답 화면에서 설정 탭, 입력 초안 유지, 투자기간 저장, CMA 평가액, 판단 유보 및 정량 지표 표시를 검증했습니다.


## 1.11.0 실제 웹 검색·CMA 잔액 반영

설정의 **웹 검색** 탭에서 Tavily 키를 저장하고, **AI 분석·운용 → 뉴스·공시 웹 검색 포함 → 설정 저장 → 1회 분석** 순서로 사용합니다. 자동 운용을 시작한 경우에도 저장한 검색 옵션을 사용합니다. 기존 설정은 검색 꺼짐을 유지합니다.

- 종목명·코드만 Tavily에 전달해 최근 한 달 뉴스와 최근 1년 DART/KIND 기업 보고서를 검색합니다. 종목당 2회, 쿼리당 최대 3개 발췌를 사용하며 동일 키·검색은 15분간 메모리에 캐시합니다. 계좌·잔고·분석 목표는 Tavily에 전송하지 않습니다.
- 검색 발췌를 현재 선택한 AI 제공사에 전달합니다. 종목별 인용 ID를 검증하고 출처 링크·게시일·수집일·검색 크레딧을 결과에 저장합니다. 링크는 EXE의 기본 브라우저에서 엽니다. 검색 오류·빈 결과·게시일 누락을 표시하며 전체 검색 실패 시 분석을 중단합니다.
- 검색 발췌는 원문 전체나 검증된 재무제표가 아닙니다. 공시가 검색되지 않으면 확인된 것처럼 판단하지 않습니다.
- 이 계좌의 `NHKRCMA` 상품(예: CMA 발행어음)을 현금성 운용 잔액으로 구분합니다. API 예수금과 CMA 잔액 및 합계를 분석에 전달하되, 총자산·주문가능금액에 다시 더하지 않습니다. 실제 매수 여력은 계좌 및 종목별 현금 주문가능금액으로 확인합니다.
- 1.10.0의 설정 탭, 유지/판단 유보 구분, 정량 지표, 투자기간, 계좌 총자산 조회를 포함합니다. 기존 키·분석 이력·모드 설정을 보존합니다. 이전 분석 결과는 변경하지 않으므로 수정된 판단은 새로 분석해야 확인할 수 있습니다.

검증: Python 테스트 182개, ESLint, Electron 문법 확인, Vite 및 Windows EXE 빌드 통과. 가상 계좌 UI에서 웹 검색 설정 저장 → 1회 분석 → CMA 잔액·판단 유보·출처 표시를 확인했습니다. 저장된 Tavily 키로 삼성전자 공개 자료 검색 2회(2크레딧)를 실행해 뉴스 3건·공시 2건 수신을 확인했습니다. 실제 주문은 실행하지 않았습니다.

- DART 연동은 포함하지 않았으며 기존 키·계좌 설정을 사용합니다. 가상 성과 추적과 변화 기반 자동 분석은 후속 범위입니다.

## 1.14.0 DART 설정과 재무·공시 분석

설정 → **DART 재무·공시**에서 인증키를 저장하고 **DART 연결 확인**을 누릅니다. **AI 분석에 재무·공시 자료 포함**을 켜고 저장하면 다음 1회/자동 분석부터 적용합니다. 키가 없거나 포함을 끄면 기존 분석을 사용합니다. 키는 기존 AI 설정과 함께 Windows DPAPI로 암호화하며, 삭제 시 DART 포함도 해제합니다.

- 공식 종목·기업 매핑 ZIP을 읽고 기업개황의 종목코드를 다시 대조합니다. 이름으로 유사 기업을 추정하지 않습니다.
- 최근 90일 공시 최대 20건과 최근 2년 정기공시 최대 20건을 조회합니다. 정정 접수일보다 보고기간을 우선하여 최신 기간을 선택합니다. 전체 공시 본문·주석은 수집하지 않습니다.
- 12월 결산법인의 연결 재무제표를 우선하고, 데이터 없음(013)에만 별도 재무제표를 조회합니다. 매출·영업이익·순이익·자산·부채·자본·영업현금흐름 주요계정을 선별합니다. 단일 항목으로 확인되지 않는 계정은 미확인으로 남깁니다. 다른 결산월은 공시 목록만 제공하고 재무기간을 추정하지 않습니다.
- 3개월 손익, 누적 손익, 시점 잔액, 비교 금액, 통화, 연결/별도, 보고기간, 접수일, 조회일을 구분합니다. 재무 수치와 공시 원문 링크는 종목 상세에서 펼쳐 볼 수 있습니다. 모델의 DART 인용도 실제 조회한 동일 종목 출처인지 검증합니다.
- 공식 호스트에만 요청하며 리다이렉트를 따라가지 않습니다. 요청 URL의 인증키는 HTTP 로그에서 가립니다. 기업 매핑은 최대 24시간, 조회 응답은 최대 15분 메모리 캐시를 사용하고 수집 시점을 표시합니다. 조회 실패·누락은 분석 결과에 표시하며 0으로 대체하지 않습니다.
- 설정 변경은 기존 상태 버전 검증을 적용합니다. DART 포함 여부가 다른 분석은 이전 판단 비교 대상으로 연결하지 않습니다. 계좌정보·AI 키는 DART로 보내지 않습니다.

공식 계약: [고유번호](https://opendart.fss.or.kr/guide/detail.do?apiGrpCd=DS001&apiId=2019018), [기업개황](https://opendart.fss.or.kr/guide/detail.do?apiGrpCd=DS001&apiId=2019002), [공시검색](https://opendart.fss.or.kr/guide/detail.do?apiGrpCd=DS001&apiId=2019001), [단일회사 전체 재무제표](https://opendart.fss.or.kr/guide/detail.do?apiGrpCd=DS003&apiId=2019020).

## 1.18.0 분석 자료 신뢰도와 사후 관측

- 매수가능수량 조회의 가격을 정수 원 단위로 전송합니다. HTTP 오류·응답 코드·실패 단계만 남기며 원문 오류·키·계좌번호는 진단에 포함하지 않습니다. 실제 조회에서 float 가격의 IGW40011 오류와 정수 가격의 정상 응답을 대조했습니다.
- 평가액과 계좌 비중은 같은 잔고 응답으로 계산합니다. 종목 상세에서 잔고 평가가격·별도 조회 시세·확정 일봉 종가 및 조회 시각을 구분합니다.
- 60구간 수익률에는 기준 종가를 포함한 61개 확정 일봉을 유지합니다. 기간별 요청에 기준 봉과 장중 제외용 봉을 확보합니다.
- Tavily 결과는 회사명·종목코드의 경계, 발행 기업, 날짜와 본문을 검사합니다. 무관한 기업·오래된 기사·공시 메뉴만 있는 자료를 제외하고 자료 부족일 때 종류별 한 번만 재검색합니다(종목당 최대 4회). 동일 조회는 15분 캐시하며 한국어 결과를 요청합니다. 웹 출처 본문은 모델 입력에 한 번만 전달합니다.
- 분석 설정의 보유 목적·종목 비중 검토 기준·분석 후 하락 재검토 기준은 선택 입력입니다. 자동 주문 한도나 강제 손절 조건이 아닌 분석 참고 기준입니다. DART를 끈 분석에는 재무자료 미포함을 명시합니다.
- 새 분석부터 정제 전 일봉·검증 일봉·시세·지표·설정·시스템 지침을 동일 DB의 별도 ai_inputs 테이블에 원본 기록으로 보관합니다. 입력 기록은 덮어쓰지 않으며 최근 200개 분석 보존 범위에 맞춰 관리합니다. 결과의 분석 입력 기록에서 JSON을 내려받을 수 있습니다. 계좌번호·인증정보는 기록에서 제외합니다.
- 분석 후 가격 관측을 직접 조회하면 기준 종가 이후 5·20·60개 거래 관측의 가격 변화·종가 최대 낙폭·KODEX 200 ETF 대비 변화를 저장합니다. 실제 체결 수익률·지수 수익률·적중률이 아닙니다. 판단 유보는 따로 집계하며 구버전 원본 없는 기록은 소급 계산하지 않습니다. 기준일 가격이 바뀌거나 조회 구간이 부족하면 계산하지 않습니다. 조회는 시세만 사용하며 AI 생성·주문을 실행하지 않습니다.

검증: Python 262개·Node 9개 테스트 및 ESLint 통과. 1280px 분석 결과와 900px 설정 화면, 선택 기준 저장·비우기, 관측 결과 재접속 보존을 가상 환경에서 확인했습니다. Vite·PyInstaller·Portable/설치 EXE 1.18.0 빌드 완료. 실제 세 종목의 매수가능금액·수량은 읽기 전용 조회로 확인했으며 유료 AI·Tavily 호출과 실전 주문은 수행하지 않았습니다. 기존 분석 내용은 그대로 보존되고 원본 보관·새 필터는 새 분석부터 적용됩니다.

## 1.19.0 API 연결 상태와 간결한 분석 결과

- 설정 상단에 나무·선택 AI·Tavily·DART의 마지막 연결 확인 결과와 한국 시각을 함께 표시합니다. 키 저장, 미확인, 확인 중, 확인 성공, 실패를 구분하고 24시간이 지난 성공은 재확인 필요로 표시합니다. DART의 분석 포함 여부는 인증 결과와 별도로 보여줍니다.
- AI는 인증·모델 목록, 나무는 계좌 조회, DART는 기업 조회, Tavily는 사용량 조회를 확인합니다. 이 결과를 주문·AI 응답 생성·모든 종목 자료의 사용 가능 보장으로 표시하지 않습니다. Tavily 확인은 [공식 GET /usage](https://docs.tavily.com/documentation/api-reference/endpoint/usage)를 사용하며 검색하지 않습니다. 한도 미설정(null) 응답도 처리합니다.
- AI·Tavily·DART 확인 실패와 시각은 암호화된 설정에 보존됩니다. 키 교체·삭제 시 확인 상태를 초기화하고, 확인 도중 설정이 변경되면 오래된 결과가 덮어쓰지 않습니다. 연결 요청 응답을 받지 못하면 서버 상태를 재조회해 실제 결과를 표시합니다. 상태 조회만으로 유료 분석을 실행하지 않습니다.
